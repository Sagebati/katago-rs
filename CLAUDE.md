# katago-rs: instructions for coding agents

## What this repo is

A file-by-file Rust port of KataGo's analysis engine (upstream v1.16.5, `ba938676`), compiled
to wasm so KataGo runs in the browser: WebGPU via burn + wgpu, with a single-threaded wasm CPU
fallback. Networks are not ported as Rust layer code: `tools/bin2onnx` converts `.bin.gz` to
ONNX and burn-onnx generates the model (`crates/katago-nn-burn`). Everything else (board,
rules, NN inputs, evaluator, search, analysis protocol) is ported by hand from `upstream/`.

- `upstream/KataGo/`: submodule pinned to the tag in `port-manifest.toml`. **Never modify it.**
- `crates/katago-core/`: the port. Mirrors `upstream/KataGo/cpp/` 1:1. No burn dep, wasm-safe.
- `crates/katago-nn-burn/`: burn-onnx-generated nets (`NetId` lists them), the backend (`backend.rs`, ported NeuralNet
  glue), the GPU conv lowering (`conv.rs`, cubecl kernels in `wino/`).
- `crates/katago-cli/`: the native `katago-rs analysis` binary (katago-ws's engine). `crates/katago-wasm/`: the
  browser engine (Web Worker). `crates/katago-annotate/`: katago-ws's game annotation, IO-free. `packages/katago-web/`:
  the npm package over katago-wasm.
- `tools/bin2onnx/`: converter + `verify.py` (checks against real KataGo). `tools/manifest_check.py`.
  `tools/annotate-parity/`: a separate cargo workspace that replays katago-ws's own annotator (needs `../katago-ws`).
- `fixtures/`: reference data generated from upstream KataGo, checked in.
- `docs/PORTING.md`: **the binding porting guide** (type/idiom/crate maps, forbidden list,
  markers). `docs/OWNERSHIP.tsv`: ownership class of every pointer field in the big classes.
  `docs/M0-report.md`: what the spike established.

New crates and tools (the planned `xtask`, ...) go at the paths in `port-manifest.toml`; do not invent
others.
The one exception is `crates/katago-core/src/port/`: helpers with no upstream file (C++
semantics shims, printf/stream formatting, the nlohmann `dump` port, node arena, executor);
see docs/PORTING.md and docs/DECISIONS.md. `docs/OWNERSHIP.tsv` is generated by
`tools/gen_ownership.py` (`python3 -I tools/gen_ownership.py docs/OWNERSHIP.tsv`): edit the script, not the TSV.

## The rule: fidelity over idiom

The 1:1 shape is what keeps following upstream cheap, so the port stays close to the C++ even
where it is not idiomatic Rust: same file split, type names, function names (snake_case),
constants verbatim (`NUM_FEATURES_SPATIAL_V7`), argument order, out-params as `&mut`,
control-flow order, comments. Idiomatic refactoring is never part of a port. The few required
divergences (exceptions → `Result<_, KataError>`, threads → async virtual threads, atomics/mutexes
→ `Cell`/`RefCell`, global init → `OnceLock`) are listed in PORTING.md and recorded in the
module's `notes` in `port-manifest.toml`.

Read `docs/PORTING.md` before porting anything and follow it over this file if they disagree.
Do not restate or reinterpret it here; if it is wrong or silent on a case, say so in your
report and mark the code `// TODO(port): <reason>` rather than guessing.

## Mirrored paths and tags

- `cpp/game/board.cpp` + `board.h` → `crates/katago-core/src/game/board.rs`, etc. The exact
  mapping is in `port-manifest.toml`; use it, don't pick paths yourself.
- First line of every ported file: `// Ported from KataGo cpp/<path> @ <sha>` (the commit you
  ported from, normally `[upstream].commit`). List both `.cpp` and `.h` if both were ported.
- Every ported fn, method, struct, or constant group:
  `/// upstream: Board::searchIsLadderCaptured (board.cpp)`. `xtask upstream-diff` greps
  these tags to find what to re-port (planned; `tools/manifest_check.py` stands in today), so a missing
  or wrong tag is a bug.
- Skipped upstream functions are not silently dropped: list them in the module's `notes`.

## port-manifest.toml

The sync record: every file under `upstream/KataGo/cpp/` is owned exactly once, by one
`[[module]]` `upstream` list or one `[[ignored]]` entry (format in the file header).
When you port or re-sync a module, update its entry in the same change:
`status` (`planned` → `draft` → `compiles` → `done`), `synced` (the upstream commit you
ported from), `notes` (skipped functions, divergences). Never mark `done` without the parity
tests for that module passing. Run `python3 -I tools/manifest_check.py` after editing it.

## References and fixtures

- **Reference KataGo** (fp32 Eigen CPU build from the submodule): `just katago-eigen` →
  `build/eigen/katago`. Use it to generate expected outputs (`kata-raw-nn`, `analysis`).
- **Upstream tests are the oracle; they are consumed, not ported.** Expected blocks in
  `cpp/tests/*.cpp` become fixtures (`tools/extract_*.py`, for the planned `xtask extract-tests`); analysis outputs come
  straight from `upstream/KataGo/cpp/tests/results/analysis/*.stdout`. That is why printers
  (`printBoard`, `NNOutput::debugPrint`, `printTree`) are ported exactly.
- Port the test's expectation, not your reading of the code: when Rust and the fixture
  disagree, the Rust is wrong until proven otherwise.
- Parity tiers (plan Verification): unit blocks string-equal (M1); NN input features
  bit-exact (M2); NN outputs within tolerance (flex ≤1e-5, wgpu ≤2e-4 logits); search
  `.stdout` identical moves/order/visits, values ±1e-4 (M3); corpus ≥99% same top move.
- `tools/bin2onnx/README.md` documents the ONNX graph contract and the postprocessing that
  `nneval.rs` must apply.

## Commands

All tasks go through `just` (see `justfile`):

| Command | What |
|---|---|
| `just katago-eigen` | build the reference KataGo (Eigen, fp32) into `build/eigen/` |
| `just convert <net.bin.gz> <name>` | `.bin.gz` → `models/onnx/<name>.onnx` |
| `just verify <net.bin.gz> <name>` | converted ONNX vs `kata-raw-nn` from the Eigen build |
| `just test` | native tests of every crate (nextest `quick` profile: no real-net search suites) |
| `just test-gpu [-F rocm]` | the GPU parity tests (wgpu, f32 and f16; rocm), one at a time |
| `just test-wasm` | float-sensitive katago-core oracle tests on wasm32 under node, wasm_yield, annotate parity |
| `just nn-parity` | ported NNEvaluator + burn vs upstream's Eigen NNEvaluator |
| `just search-smoke` / `search-tests` / `search-tolerance` | real-net searches vs the Eigen expected outputs (release, minutes) |
| `just analysis-goldens` / `analysis-protocol` | the analysis engine through the katago-rs binary vs upstream outputs |
| `just annotate-parity` | katago-annotate payloads byte-identical to katago-ws's |
| `just parity <backend> <net>` | burn import vs onnxruntime on the M0 fixtures |
| `just bench <backend> <net> <precision>` | native forward-pass throughput (README "Benchmarks"); also `bench-upstream`, `bench-web`, `wino-bench` |
| `just web-build` / `web-test` / `web-test-b18` | build katago-web and run its browser tests (Playwright + Chromium) |
| `just check-features` | serde_json: `float_roundtrip` on, `preserve_order` off |
| `just manifest-check` | every upstream cpp/ file owned once in `port-manifest.toml` |

Formatting: katago-core and the ported files elsewhere (`katago-nn-burn/src/backend.rs`, `host.rs`) keep
upstream's line breaks and a 2-space indent by hand; never run `cargo fmt` on them. Python tools run with the repo venv and `-I`: `.venv/bin/python -I tools/...`. Rust:
`cargo check -p <crate>`, `cargo nextest run -p <crate>` (cargo-nextest: one process per test, GPU tests one
at a time, see `.config/nextest.toml`; there are no doctests), and for wasm
`cargo check -p <crate> --target wasm32-unknown-unknown` (SIMD128 is on via `.cargo/config.toml`). The wasm
suites (`just test-wasm`) run through nextest too, with `wasm-bindgen-test-runner` as the target runner.

## Agent hygiene (from Bun's Zig→Rust port)

- Port only the files you were assigned. Commit only your own files, and only when asked.
- Never `git stash`, `git reset`, `git checkout -- <file>`, or rewrite history: other agents
  work in the same tree or in sibling worktrees.
- **Never stub a function to make things compile** (`todo!()`, `unimplemented!()`, empty
  bodies, `Default::default()` returns). If you cannot port it yet, port what you can and
  leave `// TODO(port): <reason>` at the exact spot. A flag beats a guess.
- `// PERF(port): <note>` where you kept a slow upstream shape on purpose or spotted a
  hot spot; don't optimise during the port. `// SAFETY:` on every `unsafe`.
- `assert` → `debug_assert!` only when the expression has no side effects; `testAssert` is
  always on. Preserve float evaluation order and integer wrapping/truncation semantics.
- Don't change RNG or hash algorithms, table sizes that affect outputs, or iteration order
  where outputs depend on it.
- No long-running commands (servers, watchers, full-corpus runs) unless asked. Report
  whether tests actually ran and how many passed; skipped or ignored tests don't count.
- When the guide was wrong or missing a rule, say so: we fix PORTING.md, not the diff.

## wasm constraints (katago-core and anything it pulls in)

- Single-threaded. No `std::thread`, rayon, tokio, `std::sync::Mutex`/atomics for logic,
  no blocking. Search parallelism is N playout futures on a local executor (plan §6).
- No `std::time::Instant`/`SystemTime` in core (panics on wasm32-unknown-unknown): time
  comes from an injected clock (`core/timer.rs`).
- No file or network IO in core: models arrive as bytes, configs as `&str`.
- No `anyhow`; errors are `KataError`. Logging through the `log` crate macros.

## burn notes (see docs/M0-report.md)

- CPU backend is **`flex`**, not ndarray (deprecated in burn 0.22). Depend on `burn-flex`
  with the `simd` feature directly: burn's `flex` feature omits it (3.5× slower in wasm).
- Convs are routed through `katago_nn_burn::conv::conv2d_same` by the `SameConv` burn-onnx `OpOverride` in
  `crates/katago-nn-burn/build.rs`: on GPUs 3x3 convs run as Winograd F(4x4,3x3) and 1x1 convs as an NCHW GEMM
  (cubecl kernels in `wino/`, a burn backend extension; docs/M9-report.md), other sizes as im2col + matmul;
  burn's own conv on the CPU. build.rs also fuses each batch norm + mish + mask chain into its conv's input loads
  (`fuse_bn_act`, a regex rewrite of the generated code that fails the build if it stops matching) and routes the
  board reduces to one kernel (`SpatialReduce`). `useFP16` / katago-web `precision` run the 3x3 convs in f16
  (a process-wide switch). Keep all three when regenerating models; the `.bpk` is unchanged.
- `+relaxed-simd` does not build (macerator 0.5.1). Weights are loaded at runtime
  (`LoadStrategy::Bytes`), never embedded. First run per batch shape costs 1–3 s: warm up.
- Browser start-up (docs/M4-report.md, "Start-up on WebGPU"): katago-wasm builds without burn's autotune
  (`wgpu-fixed-kernels`), calls `__wasm_call_ctors` itself (else wasm-ld wraps every export in
  the static constructors), and persists compiled WGSL through `third_party/cubecl-wgpu`, a
  patched cubecl-wgpu 0.11.2 (`[patch.crates-io]`; every change is marked `PATCH(katago-rs)`).
  Re-apply the patch when bumping cubecl.
